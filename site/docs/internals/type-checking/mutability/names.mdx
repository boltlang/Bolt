# Naming a mutability

A name like `'m`, written where `mut` or `imm` would be, is a mutability
that's the same wherever the name is:

```bolt
fn next(n: 'm Node) -> 'm Node = n.next;
fn both(a: 'm [i32], b: 'm [i32]) -> i32 = a[0] + b[0];
fn pair(a: 'm [i32], b: 'n [i32]) -> ('m [i32], 'n [i32]) = (a, b);
```

`next` gives back a node with the mutability of the one it's given, `both`
takes two arrays of the same kind, and `pair` two arrays of any kinds,
which it gives back as they are. `'` marks the name, as for labels and
Rust's lifetimes: without it, `m [i32]` would be the type `m` applied to
`i32`.

- **A name is a parameter of the function or impl** whose signature it's
  in, like a hidden one, but shared: every `'m` in the signature, its
  `where` predicates and its body is the same. Names don't need declaring:
  using one is enough. Like a hidden parameter, the caller chooses it, so
  the function can't change what has it, and
  `fn make() -> 'm [i32] = [1]` is an error: `[1]` is `imm`, not whatever
  the caller chooses.
- **Only functions, impls and structs have names.** An impl's associated
  types can use its names too: `impl[T] Iterable['m FnIter[T]] { type Iter =
  'm FnIter[T]; ... }` is for an `FnIter` of either mutability, and its
  `Iter` has the same one. An impl's names, like its type parameters, must
  be in its instance, since that's all choosing the impl decides:
  `impl[T, 'v] Iterable[Vec[T]]` is an error (E0234), and
  `impl[T] Iterable['v Vec[T]]` is what's meant. A struct declares its names, for its fields:
  see [below](#names-in-structs). A name elsewhere, like in a const, a type
  alias outside an impl, a body that isn't its function's or a field whose
  struct doesn't declare it, is an error (E0225). A name before a type that
  can't have a mutability, like `'m i32`, is E0222.
- **Types show names**, and a name for a mutability that's shared but not
  written: one that a body decides, or a variable of an inferred function.
  Such names start at `'m`, so that they don't read like the type variables
  `a`, `b`, ...:

  ```bolt
  fn pick(c, a, b) = if c { array_len(a); a } else { b };  // forall a. fn(Bool, 'm [a], 'm [a]) -> 'm [a]
  fn same(xs: [i32]) -> [i32] = xs;                         // fn('m [i32]) -> 'm [i32]
  fn size(xs) = array_len(xs);                              // forall a. fn([a]) -> i32
  ```

  A mutability that appears once isn't named: it's either, and it isn't
  linked to anything.

## Names in structs

A field without `mut` or `imm` has its struct's mutability, so a `mut`
iterator can't hold an `imm` array. A struct can declare a name for a field
instead, after its type parameters
([#243](https://github.com/boltlang/Bolt/issues/243)):

```bolt
struct VecIter[T, 'v] { data: 'v Vec[T], index: i32 }

fn start[T](v: 'v Vec[T]) -> mut VecIter[T, 'v] = mut VecIter { data: v, index: 0 };
```

`start` takes a `Vec` of either mutability, and gives a `mut` iterator over
it: the iterator's `index` can change, and its `data` has the mutability of
`v`. A type gives the names after its type arguments, like
`VecIter[i32, imm]`. One that isn't given is decided like the mutability
before a type: a parameter in a function's signature, an unknown in a
body, and the struct's own in a field. More than the struct declares is an
error (E0232), and so is a name declared by an item that isn't a struct, a
function or an impl (E0233). A function or an impl can declare its names
too, but doesn't have to.

**A name is at most its struct's mutability.** An `imm VecIter[i32, mut]`
would hold a `mut Vec`, which `imm` being deep rules out. So making a
struct adds `'v ⊑ m` for each name its fields have, where `m` is its
mutability, and what a field with a name holds is at most that name: `T ⊑
'v` for `data: 'v Vec[T]`:

```bolt
mut VecIter { data: mut_vec, index: 0 }   // fine: mut VecIter[i32, mut]
VecIter { data: mut_vec, index: 0 }       // error (E0223): an `imm VecIter[i32, mut]` can't have a `mut` mutability argument
fn frozen[T](v: 'v Vec[T]) -> imm VecIter[T, 'v] where 'v: imm = VecIter { data: v, index: 0 };
```

The last one needs `'v: imm`, or `'v` could be `mut`. It doesn't need
`T: imm`: `v` is a `'v Vec[T]`, so `T ⊑ 'v`, which it can assume, since
`v` exists. A struct can bound its
names, like its type parameters, which is checked where a value is made:
`struct Frozen['v: imm] { data: 'v [i32] }`.

A struct update, `VecIter { index: 1, ..it }`, keeps the names of `it`,
since the fields it doesn't give are shared. Types show a name that's
known, like `VecIter[i32, imm]`, and leave one out that's generic and
appears once, like the mutability before a type: `VecIter[T]`. One that's
left out before one that's shown is `'_`.
